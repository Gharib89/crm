# Re-run

The two re-runs of [setup-skills](../SKILL.md). Inside each paragraph, "step N" and the bold item names refer to that file's numbered steps and step 5's items.

**The profile re-run**, when the profile exists: run steps 1 to 3. Then compare the profile's `Schema:` line to ship's `metadata.profile-schema` in `.claude/skills/ship/SKILL.md`. Trailing: apply each `## Schema N` entry of [profile-schema.md](../profile-schema.md) between the two numbers in order, walking only the rows an entry adds or whose vocabulary it moves, leaving the prose under existing headings alone, and rewrite the `Schema:` line last. Ahead of ship: stop and print the refresh line; the profile is not what needs fixing. Then diff each section of the fresh exploration against the existing profile, propose only the updates, and ask whether anything else should change. Prose under the headings is the human's; update the `Label:` lines and leave the prose alone unless a fact it explains changed. Then propose step 5's closing-reference move against the existing PR template, and step 5's two dimension-label writes, the labels step 3 recorded as missing or miscased and the `## Dimension labels` section where `triage-labels.md` has none, each confirmed like every other write. With a harness present, run step 5's **Cloud bootstrap** item, and **Local gate over the harness** where the probe conformed: each writes its file where the repo has none and proposes a rewrite of the copy it finds, since a harness installed after setup reaches them no other way. End with step 6.

**A setup section re-run**, when a refresh names setup sections whose templates moved (update-skills' step 6 maps each to the item it feeds): run steps 1 to 3, whose reads the items use (step 3's host labels among them), then only those items, then step 6. For each, compare the repo's whole current copy of what the item writes (the file, the `### Ship` sub-block, the labels on the host) against the whole current template, not only the template's change since the version the repo last installed. Compare by what each part says rather than byte for byte, the template's own `setup-skills:` comment excepted. Propose each part of the template the repo lacks, and keep the repo's deliberate departures: its own wording, framing (a `### Ship` block worded around the repo's own derived copies, say) and any checks it added. For every named item, this compare replaces what the item otherwise does with a copy that already exists: updating it in place from the template (**The `### Ship` sub-block**), keeping it (**Self-contained local gate**), leaving it alone (**The `## Dimension labels` section**), proposing only listed edits (**PR template**), proposing the parts an installed Claude workflow lacks and writing one where none is installed (**Reviewer scaffolding**), or writing only where none is found (**Coding standards**, step 1.1's Azure DevOps tracker doc). **Triage labels on the host** already works on the whole label set, creating only what step 3 recorded missing, and **Local gate over the harness** and **Cloud bootstrap** already propose a rewrite of the copy they find; all three keep their rule. Write on confirm, like every other write. A section the refresh did not name is not audited.
