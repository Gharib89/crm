# The verdict comment and labels

## Labels

Exactly one of:

- **`gate-passed`** — checklist all pass/n-a, live runs green where required,
  review converged. `gh pr list --label gate-passed` is the maintainer's merge
  queue.
- **`gate-failed`** — unconverged after the gate budget, a design-level finding,
  or a checklist failure the gate can't fix in scope. The comment names the
  decision the maintainer must make (send back to author agent, re-scope, close).

Remove the opposite label if a re-run flips the verdict.

## Comment template

```
> *This was generated by AI during merge-gate review.*

## Merge gate — <gate-passed ✅ | gate-failed ❌>

Drift checklist
  1. Docs-sync            <✅ | ❌ | n/a> — <evidence / reason>
  2. E2E coverage gate    <✅ | ❌ | n/a> — <@covers / E2E_SKIP judgment>
  3. Test classification  <✅ | ❌ | n/a>
  4. Bump discipline      <✅ | ❌> — <title tier judgment>
  5. Emit contract        <✅ | ❌ | n/a>
  6. Genericity           <✅ | ❌> — <scan result>
  7. Scope discipline     <✅ | ❌> — <notes>

Integration tests
  - <target>: <profile> (whoami: <org>) → <pass | fail | skipped: reason>
  - offline suite: <✓/✗>

Fixes pushed by the gate
  - <commit>: <what and why>          (— none —)

Review dispositions
  - <finding> → <fixed | declined: evidence>

Copilot gate rounds: <n>/3 — <converged | not converged | skipped: no push>

<gate-failed only:>
Escalation: <the design-level problem / unconverged theme, and the decision
needed from the maintainer.>
```

Quote real command output for the load-bearing claims (live e2e result, local
gate) — evidence, not assertion. Keep dispositions one line each.
